# Учёт расходов

Веб-приложение (PWA) для ежедневного лимита трат. Работает без сервера и без сборки: обычные HTML, CSS и JS-модули. Данные хранятся на устройстве (IndexedDB).

## Как это считается

```
лимит дня = (база − отложка − обязательные платежи − траты за прошлые дни) / дней до конца периода (включая этот)
```

- База делится поровну на все дни периода.
- Отложка и обязательные платежи вычитаются из базы до деления.
- Платёж вычитается целиком и сразу, поэтому отметка «оплачен» на лимит не влияет, это только напоминание. Платёж можно привязать ко дню месяца: приложение покажет срок, просрочку и напомнит на экране «Сегодня» за 7 дней.
- В новом периоде платежи остаются в списке, а отметки «оплачен» сбрасываются.
- Лимит текущего дня фиксируется утром. Пока вы тратите в этот день, он не меняется, а остаток дня уменьшается.
- Недотратили или перетратили: разница сама ложится на оставшиеся дни, потому что лимит каждый день считается заново из исходных данных.
- Период задаётся двумя датами, поэтому он может начинаться не с 1-го числа (например, с дня зарплаты).

Расчёт лежит в `js/budget.js` (чистые функции) и покрыт тестами.

## Запуск

```bash
npm start            # локальный сервер на http://localhost:5173
# или любой статический сервер: python3 -m http.server 5173
npm test             # проверка формулы (Node 20+, без зависимостей)
npm run build        # пересобрать bundle.js и dist/preview.html после правок в js/
```

`index.html` можно открыть и двойным кликом: он подключает готовый `bundle.js`. Офлайн-режим (установка на экран «Домой») работает только при запуске через сервер.

**Важно:** `bundle.js` собирается из `js/*.js`. После любых правок в `js/` запустите `npm run build`, иначе страница покажет старую версию.

## Структура

| Файл | Роль |
|---|---|
| `js/budget.js` | расчёт лимитов, даты, разбор сумм |
| `js/storage.js` | хранилище (IndexedDB, запасной вариант в памяти) |
| `js/app.js` | интерфейс |
| `bundle.js` | всё вместе в одном скрипте (генерируется `npm run build`, подключается из `index.html`) |
| `js/demo.js` | пример данных для первого знакомства |
| `sw.js`, `manifest.webmanifest` | офлайн-режим и установка на экран «Домой» |

Деньги везде хранятся целым числом копеек, даты строками `YYYY-MM-DD`.

Платёж (хранится в настройках): `{ id, name, amount, dueDay, paid }`, где `dueDay` это день месяца 1–31 или `null`.

Трата: `{ id, date, amount, note, category, source, createdAt }`. Поле `source` сейчас всегда `"manual"`, позже импорт из банка будет писать туда `"bank"`.

## APK для Android

Приложение упаковывается через [Capacitor](https://capacitorjs.com/). Конфигурация уже лежит в `capacitor.config.json`, веб-часть для упаковки собирается в папку `www/` командой `npm run build`.

Получится **debug-APK**: его можно установить на свой телефон (разрешите установку из неизвестных источников). Для Google Play нужна подписанная release-сборка `.aab`, см. ниже.

### Способ 1. В облаке GitHub, без Android Studio

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки (ветка `main`).
2. Откройте вкладку **Actions**, выберите workflow **Android APK** и нажмите **Run workflow**.
3. Через 5–10 минут внизу страницы запуска, в разделе **Artifacts**, появится `expense-budget-debug-apk`. Скачайте архив, внутри лежит `app-debug.apk`.
4. Отправьте файл на телефон и установите.

Workflow лежит в `.github/workflows/android-apk.yml`. Перед сборкой он прогоняет тесты формулы.

### Способ 2. Локально (Windows, macOS, Linux)

Нужны Node.js 20+, JDK 21 и Android Studio (вместе с ним ставится Android SDK).

```bash
npm install --save-dev @capacitor/core @capacitor/cli @capacitor/android
npm run build
npx cap add android      # один раз: создаёт папку android/
npm run cap:sync         # после каждой правки кода
npx cap open android     # откроется Android Studio: Build → Build APK(s)
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`. Папка `android/` занесена в `.gitignore`: если захотите править нативную часть, уберите её оттуда и не запускайте `cap add android` повторно.

### Перед публикацией в Google Play

1. Замените `appId` в `capacitor.config.json` (`com.example.expensebudget`) на свой уникальный. После публикации менять его нельзя.
2. Соберите подписанный `.aab` (Android Studio: Build → Generate Signed Bundle) и сохраните ключ подписи в надёжном месте. Потеряв его, обновить приложение вы не сможете.

## Публикация в App Store и Google Play

Перед публикацией:

1. **Шрифты.** Сейчас они грузятся с Google Fonts. Скачайте Manrope и Unbounded в папку `fonts/`, подключите через `@font-face` и уберите `<link>` из `index.html`.
2. **Хранилище.** IndexedDB в оболочках иногда очищается системой. Для публичной версии лучше SQLite-плагин Capacitor. Достаточно написать вторую реализацию интерфейса из `js/storage.js`.
3. **Иконки и заставки.** Исходник: `icons/icon.svg`. Для магазинов удобно `@capacitor/assets`.
4. **Apple.** Приложение не должно выглядеть как «сайт в обёртке». Помогут локальные уведомления («Лимит на сегодня: 865 ₴») и работа офлайн. Нужны аккаунт разработчика ($99 в год) и Mac для сборки.
5. **Google Play.** Аккаунт разработчика ($25 один раз). Публикуется `.aab`.
6. **Политика конфиденциальности.** Нужна обоим магазинам, даже если данные не покидают устройство.

## Подключение банка (план)

1. Для Monobank есть открытый API с личным токеном (выписка и баланс). Для других банков схема сложнее.
2. Токен нельзя хранить в клиентском коде публичного приложения. Либо небольшой бэкенд, либо защищённое хранилище устройства (Keychain / Keystore через плагин).
3. Импортёр должен превращать операции банка в траты с `source: "bank"` и стабильным `id` (например, `bank-<id операции>`), чтобы повторный импорт не создавал дубликатов. Формулу расчёта менять не нужно.
4. Следующие шаги по интерфейсу: категории трат, редактирование трат, уведомления.
